## 2026-10-11 — Session 11: security-review fix on W5 (authorization bypass)
- **Finding (automated security review, after the W5 commit):** `maintenance.create` accepted an `assignedTechnicianId` and set the new ticket straight to `in_progress` with that assignee, checking only `maintenance.create` — not `maintenance.assign`. Any role holding just `maintenance.create` (including the `employee` role's self-report permission) could therefore achieve the effect of assigning a ticket to any active user, bypassing the dedicated `maintenance.assign` permission entirely.
- **Confirmed real**, not a false positive: re-read the code, found the gap exactly as described, and it is reachable (`employee` is a shipped role template with `maintenance.create` and nothing else).
- **Fix:** `createTicket` now requires `maintenance.assign` whenever `assignedTechnicianId` is supplied (matching the existing `forceAdditional` permission check right next to it); reporting a fault *without* choosing a technician still needs only `maintenance.create`, unchanged. Also addressed the review's secondary point: both `createTicket` and `assignTicket` previously verified only that the assignee was an *active user*, not that they held any maintenance permission at all — extracted a shared `assertTechnician` check (same filter as the existing `listTechnicians` query) and applied it in both places, so a ticket can no longer be assigned to e.g. an HR officer with no maintenance role.
- **New test:** `w5-maintenance.test.ts` — an `employee`-role actor is refused when supplying a technician at creation (and the ticket is not created at all, not silently downgraded); the same report without a technician still succeeds; a technically-active-but-ineligible user (HR) is refused both at creation and via `maintenance.assign`; a genuine technician assignment still succeeds.
- **Verification:** typecheck (5 projects) pass; vitest 230/230 (93 server, +1 for this fix); web E2E 42/42 unaffected (the browser's technician picker already only lists eligible users via the existing `maintenance.listTechnicians` permission gate, so no UI change was needed); prototype Electron E2E 8/8; prod audit 0.
